## 1. Продукт

### 1.1. Что это

Локальная Android-читалка для книг в формате FB2, которая показывает книгу по одному слову в режиме RSVP (Rapid Serial Visual Presentation).

Пользователь:

1. добавляет принадлежащую ему книгу FB2 или FB2.ZIP;
2. видит книгу в локальной библиотеке;
3. открывает её на паузе;
4. запускает вывод слов с выбранной скоростью;
5. ставит чтение на паузу одним касанием;
6. меняет скорость, возвращается к предложению или переходит по главе;
7. закрывает приложение и позже продолжает с того же места.

### 1.2. Главная ценность

- Удобное и предсказуемое чтение без движения глаз по строкам.
- Стабильная фокусная точка.
- Регулируемая скорость без пропущенных слов.
- Надёжное сохранение позиции.
- Полностью локальное хранение книг.

### 1.3. Не является

- Онлайн-магазином книг.
- Социальной сетью или соревнованием по скорости чтения.
- Универсальной читалкой всех форматов.
- Приложением с TTS, ИИ, синхронизацией или аккаунтом.
- Средством обхода DRM.

## 4. Архитектурные правила

- Room — единственный источник истины для каталога, пользовательских метаданных и сохранённой позиции. Содержимое книги и его целостность определяются приватными файлами и `manifest.json`. Если эти представления расходятся, книга не считается готовой: сначала выполняется безопасное восстановление из `source`, иначе книга переводится в `BROKEN`.
- Огромный текст и изображения не хранятся в Room.
- Исходный FB2 хранится в приватном файловом хранилище.
- Все операции чтения книг с диска выполняются на `Dispatchers.IO`.
- Обращения к позиции и состоянию книги сериализуются. Не допускаются параллельные записи позиции от таймера, lifecycle и UI, конкурирующие за более старую позицию.
- UI никогда не парсит FB2 и не выполняет файловые операции напрямую.
- Состояние чтения принадлежит `ReaderViewModel`, а не Composable-экрану.
- Таймер чтения изолирован от UI и тестируется с поддельным монотонным временем.
- Один экземпляр таймера на активную сессию чтения.
- Все команды таймера выполняются последовательно.
- После смены книги или выхода из чтения таймер и загрузка старой книги отменяются.
- Отложенные события старой сессии не должны изменять состояние новой.
- Работа приложения не зависит от сети.
- В манифесте не должно быть разрешения `INTERNET`.
- `android:allowBackup="false"`.
- Также должны быть отключены cloud backup и device-to-device transfer для данных приложения согласно доступным атрибутам установленного targetSdk. Для Android 12+ использовать `dataExtractionRules` и явные правила исключения всех файлов; для более старых версий — `fullBackupContent="false"`.
- Экспортируется только MainActivity, необходимая для открытия документа и приёма файла. Остальные Activity, Service и BroadcastReceiver, если появятся, должны быть `exported="false"`; лишние компоненты удаляются.
- Нельзя запрашивать `MANAGE_EXTERNAL_STORAGE` или доступ ко всей файловой системе.
- Приложение не содержит аналитики, crash reporting, рекламы и иных сетевых SDK. Логи не должны содержать текст книги, имена внутренних путей или полное содержимое URI.

## 5. Импорт FB2

### 5.1. Пути добавления

Приложение обязано поддерживать:

- кнопку добавления в библиотеке через Storage Access Framework;
- `ACTION_SEND` с MIME-типом файла;
- `ACTION_VIEW` для поддерживаемого документа.

`ACTION_SEND` и `ACTION_VIEW` принимают ровно один поток: `Intent.data` либо ровно один элемент `EXTRA_STREAM`/`ClipData`. При отсутствии потока или наличии нескольких потоков показать сообщение «Добавляйте по одной книге» и не создавать импорт.

Для `ACTION_VIEW` объявить фильтры как минимум для:

- `application/fb2+xml`;
- `application/x-fictionbook+xml`;
- `application/zip`;
- `application/x-zip-compressed`;
- `application/octet-stream` только если выбранный файл затем проверяется по содержимому.

`ACTION_SEND` может принимать `*/*`, но безопасность обеспечивает проверка потока, а не MIME-тип. Нельзя полагаться только на MIME-тип: FB2 часто определяется как `application/octet-stream`. В системном выборе разрешить выбор файла, а затем проверить содержимое.

Приложение не запрашивает persistable-доступ: оно сразу потоково копирует файл. При получении intent используется только выданное временное разрешение чтения. Если входной intent уже обработан после пересоздания Activity, повторный импорт не запускается.

### 5.2. Копирование

Сразу после получения URI:

1. открыть поток через `ContentResolver`;
2. создать временную папку `files/imports/<importId>` и технический `IMPORTING`-контекст;
3. потоково скопировать файл под именем `upload.tmp`, проверяя фактическое количество прочитанных байт, а не заявленный размер;
4. посчитать SHA-256 исходника во время копирования;
5. проверить лимиты, формат и доступный объём хранилища;
6. продолжить разбор только из приватной временной копии.

До копирования проверяется свободное место. Требуемый резерв должен покрывать как минимум размер исходника, ожидаемый `reading.txt`, ожидаемый индекс, обложку и технический запас не менее 8 MiB. Если свободного места становится недостаточно по ходу импорта, операция немедленно завершается ошибкой и освобождает временные файлы.

Один файл за операцию означает один входной поток. Одновременный запуск второго импорта из UI запрещён; импорты и финальные подтверждения сериализуются на уровне хранилища.

Запрещено:

- извлекать абсолютный путь вручную из URI;
- хранить внешний URI как основное место книги;
- читать весь файл в один `ByteArray`;
- использовать `InputStream.readAllBytes()`;
- рассчитывать на доступность внешнего файла в будущем.

### 5.3. Ограничения безопасности

Начальные лимиты:

- исходный файл: не более 50 MiB;
- распакованное содержимое: не более 250 MiB;
- количество ZIP-записей: не более 2000;
- размер одной ZIP-записи: не более 100 MiB;
- длина имени ZIP-записи: не более 1024 символов;
- глубина XML: не более 256;
- нормализованный текст: не более 50 миллионов UTF-16 code units;
- количество слов: не более 5 миллионов;
- количество XML-атрибутов на один элемент: не более 64;
- размер одного XML-текстового события, имени или значения атрибута: не более 1 MiB;
- количество сносок: не более 20 000;
- суммарный текст всех сносок: не более 8 MiB;
- текст одной сноски: не более 256 тысяч UTF-16 code units; превышение усекается по графемой границе с предупреждением;
- отображаемое название и заголовок раздела: не более 512 графем;
- отображаемое имя автора: не более 1024 графем;
- `sourceFileName`: не более 255 графем без учёта пути;
- язык: не более 64 символов;
- количество предупреждений книги: не более 10 000;
- размер обложки до декодирования: не более 10 MiB;
- размеры обложки по метаданным до декодирования: не более 4096 px по каждой стороне и не более 16 мегапикселей;

Лимиты должны быть именованными константами. При превышении показывать понятную ошибку, не аварийное завершение.

При разборе XML:

- включить обработку namespaces;
- полностью запрещать `DOCTYPE`, внешние и внутренние объявления сущностей; валидный FB2 не требует их поддержки;
- явно отключить обработку document declaration во всех доступных настройках `XmlPullParser`; если используемый движок не гарантирует отсутствие загрузки сущностей, до разбора обнаруженный `DOCDECL` должен приводить к безопасной ошибке;
- не сохранять сырые пути из ZIP как пути файловой системы;
- проверять суммарный и поштучный размер распаковки непосредственно во время потокового чтения; коэффициент сжатия использовать только как дополнительный сигнал, потому что обычный текстовый FB2 может сжиматься очень сильно;
- не доверять `ZipEntry.size` и `ZipEntry.compressedSize`: значения могут отсутствовать или быть поддельными;
- ограничивать размер буферов и накопителей текста на каждом уровне; нельзя собирать неограниченную строку из множества событий;
- не логировать текст книги.

### 5.4. ZIP

Поддерживать:

- `.fb2.zip`;
- `.fbz`;
- ZIP, определённый по magic bytes, даже если расширение неверное.

Контейнер определяется по содержимому: ZIP-сигнатура означает архив, иначе вход проверяется как XML-документ FB2. Корректная XML-книга с ошибочным расширением `.zip` также допускается; MIME и имя файла не являются единственным признаком формата.

Внутри:

- ровно один `.fb2` — импортировать;
- несколько `.fb2` — показать список выбора до показа прогресса импорта;
- ни одного `.fb2` — ошибка;
- зашифрованный или повреждённый архив — ошибка.

Расширение `.fb2` определяется без учёта регистра. Каталоги и записи с не-FB2 расширением пропускаются. Путь выбранной записи сохраняется в служебных метаданных, чтобы повторная пересборка индекса открывала именно выбранную книгу. Внутренний путь ZIP никогда не используется как путь файловой системы.

Исходный архив сохраняется как `source.fb2.zip` (или `source.fbz`) без перепаковки. Разбор идёт потоком из выбранной записи; остальные записи не распаковываются на диск. Для выбранной записи проверяются фактический размер, корректность завершения, CRC и отсутствие неподдерживаемого метода сжатия. Временная копия архива после отмены выбора или по истечении жизни сеанса выбора удаляется.

При нескольких кандидатах показывается их относительный путь и размер. Если два разных файла имеют одинаковый отображаемый путь, добавить индекс варианта, но не подменять один другим.

### 5.5. Кодировки

Поддерживать:

- UTF-8 с BOM и без BOM;
- UTF-16 LE/BE с BOM;
- Windows-1251.

Порядок определения строго такой:

1. BOM;
2. `encoding` из начального XML declaration, прочитанного как ASCII-совместимый префикс;
3. без объявления — UTF-8 по правилу XML.

Поддерживаемые синонимы `cp1251` и `windows-1251` трактуются одинаково. UTF-16 без BOM не поддерживается. Если BOM и declaration противоречат друг другу, приоритет имеет BOM, но конфликт фиксируется как предупреждение импорта. Неизвестная кодировка, запрещённая XML-кодировка, неполная многобайтовая последовательность или недопустимые для выбранной кодировки байты завершают импорт ошибкой. Замена повреждённых байт символом `�` без явного предупреждения запрещена.

После определения BOM удаляется, декодер создаётся один раз, а XML-парсер получает уже декодированный `Reader`. Повторное определение кодировки после начала разбора запрещено.

### 5.6. Поддерживаемые элементы FB2

Корневой элемент должен иметь локальное имя `FictionBook`. Namespace обрабатывается корректно, но для реальных файлов недопустимо отвергать книгу только из-за отсутствующего или нестандартного namespace, если структура `description/body` однозначно распознаётся. Остальные корневые элементы считаются не-FB2.

Поддерживать и учитывать:

- `description/title-info`;
- `book-title`;
- авторов по полям и nickname;
- `lang`;
- `coverpage` и обложку из `binary`;
- основное тело `body`;
- иерархию `section`;
- `title`;
- `p`;
- `empty-line`;
- inline-теги, включая `emphasis` и `strong`;
- `poem`, `stanza`, `v`;
- `epigraph`;
- `cite`;
- `subtitle`;
- `table`, `tr`, `td`, `th`;
- ссылки на сноски;
- `body` с именем `notes`, если он есть;
- несколько основных `body` в порядке документа;
- обычные ссылки `a`: их текст остаётся в основном потоке, переход по URL не выполняется;
- неизвестные inline- и блочные теги с извлечением текста.

Нельзя включать в основной поток:

- аннотацию книги;
- историю документа;
- выходные данные;
- служебный titlepage;
- notes body целиком;
- Base64 binary;
- дубли названий из title-info.

Название и авторы из `description/title-info` используются только как метаданные. Для нескольких авторов сохраняется порядок полей `first-name`, `middle-name`, `last-name`, `nickname`; пустые части схлопываются, авторы разделяются строкой «, ». Если поля имени противоречивы или отсутствуют, использовать непустой `nickname`, затем «Автор неизвестен». Язык сохраняется как исходное значение, если оно непустое; UI не требует загрузки локали.

Слишком длинные метаданные не ломают импорт: они обрезаются по графемой границе до лимита из раздела 5.3, а в предупреждениях книги отмечается усечение. HTML/XML-разметка в метаданных не отображается как разметка.

Основными считаются все прямые `body`, у которых имя не равно `notes` без учёта регистра. Основные body читаются в порядке документа. `body name="notes"` не попадает в основной поток, но его целевые разделы могут использоваться для сносок.

### 5.7. Семантические правила

- Основной текст читается в порядке XML.
- Канонический `reading.txt` формируется только из читаемых блоков: нормализованный текст, отсутствие нового разделителя между соседними inline-фрагментами внутри слова, перевод строки между стихотворными строками и пустая строка между обычными блоками. Служебные заголовки, обложка, метаданные и сноски в него не входят.
- Названия глав не вставляются в поток обычных слов.
- Верхнеуровневые `section` формируют главы и точки автопаузы.
- Вложенные разделы отображаются в оглавлении с отступом.
- Заголовок раздела превращается в отдельный визуальный блок, не входящий в подсчёт слов.
- Каждый раздел имеет стабильный `chapterKey` на время жизни индекса. Это путь индексов разделов внутри документа, а не отображаемое название. Изменение индекса допускает перенос позиции по сохранённому смещению и fingerprint.
- Если у раздела нет непустого заголовка, для оглавления использовать «Раздел N», где N — номер раздела на его уровне. Для синтетической главы без `section` использовать «Книга».
- Если основной текст находится непосредственно в `body` до первого `section`, он входит в синтетический раздел этого body и не теряется.
- Начало стихотворной строки получает границу `VERSE_LINE`.
- Конец строфы получает границу `VERSE_STANZA`.
- Строки простой таблицы линеаризуются в порядке `tr` слева направо: содержимое ячеек разделяется одним пробелом, пустые ячейки пропускаются, после строки ставится `TABLE_ROW`; вложенные таблицы не разворачиваются рекурсивно и линеаризуются как обычный текст в пределах лимита.
- Иллюстрация в теле книги превращается в визуальный блок «Иллюстрация» без содержимого.
- Ссылка на сноску определяется по `type="note"` и внутреннему `xlink:href="#..."` по локальному имени `href`; namespace XLink учитывается. Её видимый текст не становится отдельным словом. Если ссылка стоит после слова в том же inline-блоке, `noteId` прикрепляется к предыдущему слову; если перед текстом — к следующему. Внешние ссылки и ссылки без `type="note"` обрабатываются как обычный текст.
- Если цель сноски отсутствует, импорт не падает: ссылка пропускается, а в предупреждениях книги фиксируется отсутствующая сноска.
- Текст сноски не попадает в основной поток.
- Сноска на слово не меняет его `startChar`, `endChar` и не увеличивает `wordCount`.
- Неизвестный inline-тег сохраняет текст.
- Неизвестный блочный тег сохраняет дочерний текст и не показывает пользователю XML.
- Если в книге нет разделов, создаётся одна условная глава «Книга».
- Если нет названия, используется исходное отображаемое имя без составного расширения `.fb2.zip`/`.fbz`/`.fb2`; имя очищается от пути и управляющих символов, пустой результат заменяется на «Без названия».
- Если нет автора, используется «Автор неизвестен».

Если фрагменты внутри одного слова разделены inline-тегами, между ними не вставляется пробел. Если раздел заканчивается без знака препинания, это не добавляет знак в текст. Синтетическая пунктуация запрещена: отображаемый текст должен оставаться авторским, кроме нормализации Unicode whitespace и BOM.

### 5.8. Атомарный импорт

Импорт выполняется по схеме с явной точкой фиксации:

1. создать в Room скрытую запись со `contentState=IMPORTING` и уникальным `bookId`;
2. полностью сформировать временную папку `files/imports/<importId>`;
3. проверить исходник, канонический текст, индекс, метаданные, сноски и обложку;
4. записать `manifest.json.tmp`, выполнить flush и атомарно переименовать его в `manifest.json`; наличие валидного `manifest.json` с `state="COMMITTED"` является точкой фиксации содержимого;
5. перенести готовую папку в `files/books/<bookId>` в пределах одного `filesDir`; использовать атомарное переименование, а при недоступности платформенной атомарной операции — эквивалентный протокол «временная конечная папка + commit manifest», не делающий книгу видимой;
6. проверить повторно фундаментальные файлы;
7. в транзакции Room перевести запись в `contentState=READY` и показать её библиотеке.

Если процесс завершился до создания commit manifest, при следующем запуске связанные запись и папки импорта удаляются. Если commit manifest уже записан, но Room ещё содержит `IMPORTING`, запуск пытается завершить перенос и проверку и перевести книгу в `READY`. Если восстановить согласованное состояние нельзя, скрытая запись удаляется вместе с временными файлами; пользователь не получает книгу с частичным содержимым. Полностью успешный импорт нельзя терять только из-за падения между переносом папки и обновлением Room.

Пользователь не должен видеть наполовину добавленную книгу.

Отмена до точки фиксации удаляет временную папку и `IMPORTING`-запись. После начала финального подтверждения кнопка отмены отключается; пользователь увидит либо нормальную карточку книги, либо понятную ошибку. Все операции очистки идемпотентны и переживают повторный запуск.

### 5.9. Дубликаты

До окончательного коммита проверять:

- `sourceHash` — точный повтор файла;
- `contentHash` — повтор нормализованного содержимого.

Оба значения — SHA-256 в нижнем регистре. `sourceHash` считается по неизменённой копии входного файла. `contentHash` считается по байтам канонического `reading.txt` без метаданных, названия, обложки и времени импорта; смена parserVersion не должна сама по себе менять `contentHash`.

Дубликаты ищутся среди записей `READY`. Проверка и вставка сериализуются на уровне `AppContainer`, чтобы два параллельных импорта не создали неявные дубли в обход выбора.

При совпадении:

- показать название найденной книги;
- предложить «Открыть существующую»;
- предложить «Импортировать копию»;
- не перезаписывать прогресс существующей книги автоматически.

«Открыть существующую» открывает найденную книгу на паузе и не создаёт новый `bookId`. «Импортировать копию» создаёт отдельную запись с собственным прогрессом. Закрытие диалога отменяет импорт и удаляет временные файлы.

Совпадение только названия или автора не считать дубликатом.

### 5.10. UI импорта

Для ZIP с несколькими книгами сначала показать выбор кандидата. После выбора файла показать панель прогресса с этапом и кнопкой «Отмена». Индикатор не должен мигать: показывать его не раньше чем через 300 мс; если операция уложилась в это время, промежуточный индикатор не показывать.

Кнопка отмены доступна во время чтения и построения индекса. В интерфейсе должен быть понятный этап: проверка файла, чтение книги, подготовка текста, подготовка обложки, сохранение. Нельзя показывать техническое имя исключения.

После успеха:

- первая книга в пустой библиотеке открывается на первом слове в состоянии паузы;
- последующие книги остаются в библиотеке;
- показать snackbar «Книга добавлена» с действием «Открыть».

Ошибки не должны оставлять временные файлы.

Импорт принадлежит `LibraryViewModel` и переживает поворот экрана. Фоновый импорт после смерти процесса не обещается: незавершённая операция очищается при следующем запуске, а пользователь может повторить добавление. При возвращении из системного выбора открывается тот же диалог или панель, если Activity была пересоздана.

## 6. Файловое хранилище

Постоянные данные размещаются в `filesDir`.

```text
files/
  books/
    <bookId>/
      manifest.json
      source.fb2 | source.fb2.zip | source.fbz
      reading.txt
      reading_index.bin
      book.json
      cover.webp (опционально)
  imports/
  trash/
```

### 6.1. Назначение файлов

- `source.fb2`, `source.fb2.zip` или `source.fbz` — неизменённая приватная копия исходника. Для ZIP в манифесте отдельно хранится внутренний путь выбранной FB2-записи.
- `reading.txt` — канонический нормализованный основной текст в UTF-8.
- `reading_index.bin` — производный индекс слов, границ, предложений и глав.
- `book.json` — метаданные, оглавление, сноски, визуальные блоки и предупреждения.
- `cover.webp` — уменьшенная обложка, если она была в книге.
- `manifest.json` — версия структуры, `state="COMMITTED"`, идентификаторы, parser/index versions, идентификатор выбранной архивной записи, хэши, размеры и перечень файлов.

`manifest.json` не может ссылаться на файлы вне папки книги или содержать абсолютные пути. Все производные файлы являются заменяемыми: при их потере источник остаётся неизменным и служит основой восстановления. Исходник нельзя перезаписывать после commit.

Формат `reading_index.bin` выбирается реализацией, но обязан:

- иметь magic/version header;
- быть потоково читаемым и допускать поиск записи по `wordOrdinal`/`itemOrdinal` без загрузки всего индекса в память;
- ссылаться на позиции в `reading.txt`;
- позволять восстановить индекс из `reading.txt` и `book.json`;
- быть проверяемым по количеству слов, длине, контрольной сумме, версии формата и `contentHash`;
- не загружать книгу в память в виде DOM.

Минимальный контракт файла:

1. фиксированный header: magic, formatVersion, parserVersion, размер `reading.txt`, его SHA-256, `wordCount`, `itemCount`, `sentenceCount`, `chapterCount`;
2. таблица глав и вложенных разделов: `chapterKey`, отображаемое название, уровень, диапазон item-индексов, количество слов;
3. таблица визуальных элементов `HEADING`/`IMAGE`, привязанных к item-позиции;
4. записи слов фиксированного размера либо таблица offset-ов, позволяющая найти запись за ограниченное число чтений;
5. таблица предложений и индексов начала/конца;
6. таблица связей `noteId` со словом; сам текст сносок хранится в `book.json`;
7. footer с контрольной суммой и версией.

Полный `displayText` каждого обычного слова в индекс не дублируется: он восстанавливается из `reading.txt` по `startChar..endChar`. В индексе допустимо хранить только короткие служебные подписи заголовков и визуальных блоков.

Внутри кода последовательность отображения можно представить моделью:

```text
ReadingItem
  ordinal
  kind: WORD | HEADING | IMAGE
  lastWordOrdinal: Int?
  nextWordOrdinal: Int?
  startChar: Int
  endChar: Int
  sentenceId
  chapterIndex
  boundaryAfter
  noteIds
```

Для обычного слова `ordinal` соответствует `wordOrdinal`. Заголовки и заглушки изображений не увеличивают `wordCount`, но могут быть текущим элементом чтения и поэтому должны иметь собственный `itemOrdinal`. Смещения — в UTF-16 code units декодированной строки Kotlin. Для визуального элемента без текста смещения могут указывать на диапазон следующего слова и не используются для прогресса.

### 6.2. Обложка

- Извлекать только кавер из `coverpage`.
- Не распаковывать все body images в MVP.
- До декодирования прочитать только метаданные изображения и отклонить изображение, превышающее лимиты из раздела 5.3.
- Использовать downsample так, чтобы итоговая обложка имела длинную сторону не более 1200 px; целевое соотношение сторон сохраняется.
- Поддерживать растровые форматы, которые может декодировать платформа для сохранённой обложки: JPEG, PNG, WebP. SVG и внешние ссылки не загружать.
- Сохранять как WebP с разумным качеством; итоговый файл не должен превышать 2 MiB.
- При отсутствии или ошибке декодирования не ломать импорт: использовать генеративную заглушку.
- Генеративная заглушка строится детерминированно из книги: инициалы/первая буква названия, цвет из фиксированной палитры текущей темы и название. Она не считается `cover.webp`.
- Обложка не влияет на `contentHash` и не блокирует чтение.

### 6.3. `book.json`

`book.json` — компактный UTF-8 JSON через `kotlinx.serialization`, размер которого не превышает 16 MiB. Обязательные верхнеуровневые поля:

- `schemaVersion`;
- `metadata` — отображаемое название, автор, язык, формат;
- `toc` — массив разделов: `chapterKey`, уровень, отображаемое название, первый item/word, количество слов;
- `notes` — массив сносок: `noteId`, линейные текстовые блоки, необязательные предупреждения;
- `warnings` — коды и понятные локализуемые параметры упрощений;
- `visualItems` — заголовки/изображения-заглушки и их привязка к item-позициям.

В `book.json` запрещено хранить Base64 изображений, исходные XML-фрагменты размером с книгу и дублирование `reading.txt`. Текст сноски не должен содержать исполняемые URL-схемы; при отображении используется только текст. Неизвестные поля при чтении игнорируются, отсутствие обязательного поля делает производные данные невалидными и запускает восстановление из источника.

`book.json` записывается во временный файл, проверяется повторным чтением, затем атомарно заменяет старый. После commit manifest он считается неизменяемым до пересборки.

### 6.4. `manifest.json`

`manifest.json` — UTF-8 JSON со строгими обязательными полями:

- `schemaVersion`, `state`, `bookId`, `parserVersion`, `indexVersion`, `layoutVersion`;
- `format`, `archiveEntryPath`;
- `sourceHash`, `contentHash`;
- таблица файлов: относительное имя, роль, размер, SHA-256;
- версия `book.json` и контрольная ссылка на индекс (`wordCount`, `itemCount`, `sentenceCount`, `chapterCount`).

Поля времени, пользовательская позиция и настройки книги в манифест не входят. При проверке файла нельзя доверять только одной контрольной сумме: проверяются размер, наличие в ожидаемом каталоге и отсутствие абсолютных/выходящих за папку путей. Полный SHA-256 всех крупных файлов выполняется при импорте, восстановлении и диагностике, а обычное открытие проверяет manifest, версии и размеры, чтобы не замедлять запуск.

## 7. База данных и позиция

### 7.1. Таблица книг

Минимальная схема `books`:

- `id: String` — UUID, первичный ключ;
- `title: String`;
- `authorDisplay: String?`;
- `language: String?`;
- `format: String`;
- `sourceFileName: String`;
- `folderRelativePath: String`;
- `archiveEntryPath: String?` — выбранная запись ZIP; `null` для одиночного FB2;
- `sourceHash: String`;
- `contentHash: String`;
- `sourceSizeBytes: Long`;
- `wordCount: Int`;
- `chapterCount: Int`;
- `coverRelativePath: String?`;
- `contentState: IMPORTING | READY | BROKEN | DELETING`;
- `readingState: UNREAD | READING | COMPLETED`;
- `currentItemOrdinal: Int`;
- `currentCharOffset: Int`;
- `currentWordIndex: Int`;
- `currentSentenceId: Int?`;
- `currentChapterKey: String?`;
- `currentChapterTitle: String?`;
- `positionFingerprint: String?`;
- `positionRevision: Long`;
- `progressPercent: Int`;
- `lastSpeedWpm: Int?` — `null` до первого выбора скорости для этой книги;
- `parserVersion: Int`;
- `indexVersion: Int`;
- `layoutVersion: Int`;
- `importedAt: Long`;
- `lastOpenedAt: Long?`;
- `lastSavedAt: Long?`;
- `lastErrorCode: String?`.

Список библиотеки показывает только `READY`, `BROKEN`.

`format` принимает `FB2` или `FB2_ZIP`. Значение определяется по фактическому содержимому, а не по расширению. `sourceFileName` хранит только безопасное отображаемое имя без каталогов, управляющих символов и неограниченной длины; полный внешний URI не сохраняется.

`chapterCount` означает число непустых верхнеуровневых `section`, содержащих хотя бы один WORD в себе или в потомках; синтетическая глава «Книга» и пустые разделы в него не входят. Вложенные разделы не увеличивают `chapterCount`, но входят в оглавление. `wordCount` равен нулю только для невалидной книги; такая книга не становится `READY`.

Индексы обязательны как минимум по:

- `contentState, lastOpenedAt`;
- `readingState, lastOpenedAt`;
- `sourceHash`;
- `contentHash`.

`id` первичный, но `sourceHash` и `contentHash` не делаются уникальными: пользователь может явно импортировать копию. `progressPercent` — производный кэш для списка; его значение вычисляется по формуле из раздела 8 и обновляется в той же транзакции, что и позиция. Каноническими полями прогресса остаются `currentWordIndex` и `wordCount`.

`layoutVersion` описывает совместимость сохранённых визуальных элементов и структуры `book.json`, а не версию Compose или оформления. При смене этого поля применяется та же безопасная пересборка производных данных, что и для `indexVersion`.

### 7.2. Состояния

Читательская часть:

- `UNREAD` — пользователь ещё ни разу не нажимал Play для этой книги;
- `READING` — пользователь хотя бы один раз нажал Play, но книга ещё не завершена;
- `COMPLETED` — книга дочитана.

Нажатие Play на `UNREAD` переводит книгу в `READING` до запуска первого интервала. Поэтому карточка «Продолжить» появляется даже тогда, когда пользователь остановился на первом слове. Сброс и «Читать заново» возвращают `UNREAD`; `COMPLETED` выставляется только после показа последнего WORD и завершения финальной задержки.

Техническая доступность:

- `IMPORTING` — скрыта;
- `READY` — доступна;
- `BROKEN` — видима как проблемная;
- `DELETING` — скрыта.

`READY` допустим только при наличии валидного commit manifest и файлов, перечисленных в нём. Недостающий производный файл не обязательно делает книгу `BROKEN`: сначала выполняется восстановление из `source`. `BROKEN` выставляется только после неудачного восстановления или при повреждении самого источника. Переходы в `BROKEN` и обратно в `READY` выполняются транзакционно и отражаются в библиотеке.

Успешное восстановление переводит книгу в `READY` и очищает `lastErrorCode`; повторное открытие не обязано заново пересобирать индекс. Ошибка, которая не влияет на чтение (например, отсутствующая необязательная обложка), не меняет `contentState`.

### 7.3. Позиция

Каноническая позиция:

- `currentItemOrdinal` — точный индекс текущего элемента отображения, включая заголовок или заглушку изображения;
- `currentCharOffset` — начало текущего слова в `reading.txt`; для элемента без слова — начало ближайшего следующего слова, а если его нет — конец текста;
- `currentWordIndex` — индекс последнего отображавшегося обычного слова; для начального визуального блока до первого слова использовать `-1`;
- `positionFingerprint` — первые 16 байт SHA-256 от нормализованного текущего отображаемого текста и не более 64 символов контекста слева и справа;
- `currentChapterKey` — стабильный путь раздела.

Текущий элемент — это слово, заголовок или заглушка, которая сейчас показана на экране. Для обычного слова позиция одновременно является последним показанным словом. Следующее слово или следующий визуальный блок сохранять не надо.

При восстановлении:

1. проверить manifest и загрузить подходящий индекс;
2. проверить диапазон `currentItemOrdinal` и найти элемент;
3. для слова сверить `currentCharOffset` и fingerprint; для визуального элемента проверить его тип, главу и ближайший word-якорь;
4. при точном совпадении открыть сохранённый элемент;
5. при расхождении искать fingerprint в пределах сохранённой главы, предпочитая позицию, ближайшую к `currentCharOffset`;
6. если контекст не найден, использовать `currentWordIndex`, если он попадает в главу и совместим с fingerprint;
7. затем открыть первый элемент сохранённой главы;
8. если глава недоступна, открыть начало книги с уведомлением.

Если индекс был пересобран и текст изменился, применение старой позиции без проверки fingerprint запрещено. Уведомление о неточном восстановлении показывается один раз на открытие и не повторяется при каждом повороте экрана.

### 7.4. Частота сохранения

- при ручной паузе — сохранение в Room ожидается до завершения видимого перехода UI в `Paused`;
- при переходе по предложению или главе — позиция фиксируется до возврата управления таймеру;
- при завершении — точная финальная позиция и `COMPLETED` в одной транзакции;
- при переходе приложения в фон — текущий элемент немедленно записывается в `SavedStateHandle`, затем выполняется запись в Room; это защищает от потери позиции при уничтожении процесса до окончания фоновой записи;
- при выборе «Библиотека» или Back — запись в Room завершается до навигации; если она длится дольше 300 мс, показать ненавязчивый индикатор сохранения;
- во время чтения — не реже раза в секунду или на границе предложения.

`positionRevision` — монотонно возрастающий счётчик сохранённых изменений позиции в рамках книги. Каждая команда изменения позиции получает новую ревизию; запись в Room применяется только если её ревизия не меньше текущей. `lastSavedAt` используется для отображения и сортировки, но не для разрешения гонок. Сброс и «Читать заново» также инкрементируют ревизию, чтобы старая отложенная запись не вернула прежнее место.

Запись позиции должна быть идемпотентной. При внезапном падении процесса во время активного чтения допустима потеря не более примерно одной секунды. При ручной паузе, переходе по предложению/главе, Back, завершении и уходе в фон потеря текущего элемента недопустима: текущая позиция должна восстанавливаться из Room или `SavedStateHandle`.

Если Room вернул ошибку записи во время чтения, пользователь остаётся на текущей странице, видит одно понятное предупреждение и может продолжить чтение. Повторные ошибки не создают серию snackbar; при восстановлении записи предупреждение можно закрыть.

Если ошибка возникла при обязательном сохранении перед Back/выходом, навигация не выполняется молча. Пользователь видит диалог с точками «Повторить» и «Выйти без сохранения»; второй выбор является явным подтверждением потери последней позиции. При уходе приложения в фон такой диалог не показывается, а `SavedStateHandle` сохраняет checkpoint.

### 7.5. Транзакции и уборка

- Импорт невидим до полной готовности.
- Удаление: сначала перевести запись в `DELETING`, затем атомарно переместить папку книги в `trash/<bookId>-<uuid>`, затем удалить запись из Room, затем очистить папку из `trash`.
- Удаление идемпотентно: повторный запуск после падения завершает очистку, даже если папка уже отсутствует.
- При старте очищать или завершать незавершённые импорты и удаления по правилам разделов 5.8 и 7.5.
- При старте удалять только содержимое `trash`, принадлежащее записям `DELETING` или имеющее валидный технический маркер того же формата; остальное оставить и зафиксировать для диагностики.
- Не удалять незнакомые постоянные папки без подтверждённого manifest и отсутствия ссылки из базы.
- Незнакомую папку в `books/` нельзя молча удалять; при её наличии записать безопасное диагностическое событие без содержимого книги и оставить её до отдельного решения разработчика.
- Все пути в базе — относительные.
- Любая операция над папкой сначала нормализует путь и проверяет, что он остаётся внутри `filesDir`. Символьные ссылки и `..` в путях запрещены.

### 7.6. Обновления

Версионировать отдельно:

- Room schema;
- parser version;
- reading index version;
- layout version.

Запрещено использовать destructively recreate database при миграции.

При изменении parser/index version:

- пересобирать производные файлы из сохранённого `source`;
- не удалять источник;
- новый индекс создавать рядом, проверять и затем заменять старый;
- при ошибке оставлять старый рабочий индекс;
- пересборку делать лениво при открытии книги.
- для ZIP использовать сохранённый `archiveEntryPath`, а не выбирать первый `*.fb2` повторно;
- обновлять `parserVersion`/`indexVersion` только после успешной проверки нового индекса и его совместимости с текущим `reading.txt`;
- не менять пользовательскую позицию и `readingState` во время пересборки;
- Room-миграции тестировать на подготовленной базе предыдущей версии; `fallbackToDestructiveMigration` запрещён.

Пересборка должна иметь явный crash-safe протокол. Новый набор `reading.txt`, индекса и `book.json` целиком создаётся в отдельном временном каталоге внутри папки книги, проверяется по размерам и хэшам, после чего фиксируется атомарным manifest-переходом. Пока переход не завершён, библиотека и Reader продолжают использовать старый рабочий набор; после успешного перехода обновляются версии в Room и только затем удаляется старый. При старте незавершённая пересборка либо откатывается к старому набору, либо безопасно завершается по записанному journal; смешанный набор файлов разных поколений недопустим. Такой протокол можно реализовать версионированными именами файлов или поколениями в подкаталоге — конкретный способ выбирает реализация, но инварианты обязательны.

Если процесс упал между manifest-переходом и обновлением Room, при старте актуальные `parserVersion`/`indexVersion`/`layoutVersion` восстанавливаются из валидного manifest и Room синхронизируется с ним. Если Room ожидает более новую версию, чем подтверждена manifest, книга должна быть восстановлена из источника, а не считать «половину» нового набора актуальной.

## 8. Токенизация

Канонический текст `reading.txt` должен быть детерминированным: одинаковый исходник, parserVersion и нормализация дают одинаковые байты. Перед записью/токенизацией:

- привести Unicode к NFC;
- удалить управляющие символы и мягкий перенос;
- заменить неразрывный и другие горизонтальные Unicode-пробелы обычным пробелом; неразрывный пробел считается границей слов для RSVP;
- нормализовать переводы строк;
- сохранить регистр, `ё`, авторские кавычки и пунктуацию.

Нормализация выполняется так, чтобы составная графема или surrogate pair не разрывались между блоками. После завершения импорта `reading.txt` не меняется до пересборки из источника.

Правила токенизации:

- слово — непустая последовательность символов между Unicode whitespace-границами;
- inline-разметка не создаёт новое слово и не добавляет пробел между фрагментами одного слова;
- блочная граница создаёт границу слова, но не создаёт пустой токен;
- `кто-то`, `Москва-река`, десятичные числа и URL — один токен;
- начальные кавычки и открывающие скобки относятся к следующему слову;
- завершающие кавычки, скобки, многоточие и знаки препинания относятся к предыдущему слову;
- длинное или среднее тире в начале реплики прикрепляется к следующему слову, но не создаёт отдельный такт;
- отдельный пунктуационный токен не создаёт отдельный такт;
- сокращение и инициал отображаются как отдельные слова, если отделены пробелом;
- пустые строки и границы блоков не считаются словами;
- заголовки и визуальные блоки не увеличивают `wordCount`;
- прогресс считается только по словам.

Если в исходнике есть одиночная пунктуация между пробелами, она присоединяется к предыдущему слову того же блока, если оно есть; иначе становится префиксом следующего слова. Если после такого присоединения в блоке не остаётся ни одного читаемого слова, блок пропускается. Две роли одновременно (суффикс и префикс) разрешены только для парной кавычки/скобки и не создают новый такт.

Для языков без пробельного разделения слов (например, CJK) MVP не обещает корректную пословную разбивку: такой абзац может отображаться как один длинный токен с защитой от обрезания. Это должно быть указано в README как известное ограничение; формат FB2 при этом не отвергается.

Чтобы патологический токен не мог заблокировать Compose или скрыть текст, вводится `MAX_TOKEN_GRAPHEMES = 96`. Логический токен длиннее 96 графем делится на последовательные WORD-сегменты не длиннее 96 графем строго по графемным границам. Сегменты попадают в `wordCount`, получают minimum dwell как длинные слова и создают одно предупреждение книги «Фрагмент без пробелов разделён для отображения». Символы не удаляются. Если заметка была привязана к логическому токену, она прикрепляется к последнему сегменту.

`wordOrdinal` и `itemOrdinal` нумеруются с нуля. `wordCount` — число WORD-элементов. Для фокусной буквы использовать графемные кластеры, а не UTF-16 code units или простые `Char.length`.

Прогресс вычисляется так:

```text
progressPercent =
  100, если readingState == COMPLETED;
  0, если readingState == UNREAD или currentWordIndex < 0;
  clamp(floor(100 * (currentWordIndex + 1) / wordCount), 1, 99) в остальных случаях.
```

Пока последнее слово показано, но финальная задержка ещё не завершилась, прогресс остаётся 99%, а не «Прочитано». Заголовки и изображения не меняют `currentWordIndex`.

## 9. Движок чтения

### 9.1. Диапазон скорости

- минимум 100 слов/мин;
- максимум 800 слов/мин;
- шаг 25;
- пресеты: 200, 300, 400, 500, 750;
- значение по умолчанию: 300;
- у каждой книги своё последнее значение;
- глобальное значение используется только для книги без сохранённой скорости.

Любое значение из слайдера нормализуется к ближайшему числу, кратному 25, и ограничивается диапазоном. Эффективная скорость книги равна `lastSpeedWpm`, если он задан, иначе глобальной скорости по умолчанию. Изменение скорости в `Paused` записывает `lastSpeedWpm` для текущей книги немедленно и применяется при следующем Play; первый Play также фиксирует текущую эффективную скорость как персональную скорость книги. Изменение глобальной скорости по умолчанию не перезаписывает уже заданную скорость книг. Кнопки `−`/`+` неактивны на границе диапазона. Сброс книги сохраняет `lastSpeedWpm`.

### 9.2. Базовый расчёт

```text
baseMs = round(60000 / wpm)
```

Результат приведения — целое число миллисекунд, не меньше 1. Скорость означает базовый темп одного обычного WORD-элемента до дополнительных пауз.

При старте и возобновлении текущий элемент удерживается; для обычного WORD используется:

```text
resumeDwellMs = max(400, baseMs)
```

Дополнительные паузы после элемента:

- `CLAUSE`: `max(baseMs * 0.20, 25)`;
- `SENTENCE`: `max(baseMs * 0.60, 60)`;
- `VERSE_LINE`: `max(baseMs * 0.40, 40)`;
- `VERSE_STANZA`: `max(baseMs * 1.00, 100)`;
- `PARAGRAPH`: `max(baseMs * 1.00, 100)`;
- `TABLE_ROW`: `max(baseMs * 0.60, 60)`;
- `CHAPTER` и `BOOK_END` не складываются с этими паузами, а управляют состоянием.

Если после слова установлено несколько флагов, применять только самую сильную паузу, а не сумму.

Приоритет:

```text
BOOK_END > CHAPTER > PARAGRAPH = VERSE_STANZA > SENTENCE >
TABLE_ROW > VERSE_LINE > CLAUSE > NONE
```

Все длительности вычисляются в миллисекундах и округляются до целого один раз. Отрицательные и дробные значения не попадают в планировщик.

`HEADING` и `IMAGE` являются отдельными визуальными элементами только в последовательности отображения; они не являются WORD и не влияют на `wordCount`. Специальный визуальный блок показывается:

```text
max(1200, baseMs * 2)
```

Последнее слово книги показывается не меньше:

```text
max(400, baseMs * 1.5)
```

После него приложение переходит в `Completed`; переход не проскакивает финальную задержку.

Первый экран книги открывается на первом WORD-элементе в `Paused`, а название первой главы отображается в шапке паузы. При автоматическом переходе в следующую короткую главу её заголовок может быть показан как отдельный визуальный элемент перед первым словом. При `ChapterBreak` заголовок уже показан на экране перерыва, поэтому Play сразу переводит к первому слову следующей главы и не показывает дублирующийся заголовок.

### 9.3. Планировщик

- Использовать монотонное время, например `SystemClock.elapsedRealtime()`.
- Держать один активный coroutine-job таймера.
- Каждый следующий элемент показывается отдельным переходом состояния; нельзя переходить сразу через несколько элементов.
- Обычная задержка меньше `min(25 мс, 20% текущего интервала)` может компенсироваться, чтобы не накапливать систематическое отставание. После более длинной задержки показать только следующий элемент и начать новый интервал от фактического времени его показа.
- Никогда не пропускать элемент ради «догоняния» темпа. При устойчивой нехватке производительности фактическая скорость может снизиться, но число показанных элементов и их порядок не меняются.
- Повторный `play` во время `PLAYING` не создаёт второй таймер.
- Повторный `pause` не запускает никаких дополнительных эффектов.
- При паузе отменять таймер.
- На паузе не держать «остаток» текущей задержки.
- При возобновлении текущий элемент снова показывается в течение `max(resumeDwellMs, собственный dwell элемента)`; для HEADING/IMAGE это не отменяет минимальные 1200 мс. Оставшаяся задержка паузы не сохраняется.
- Смена скорости не запускает таймер и не меняет текущий элемент. Если смена произошла программно во время `Playing`, новый интервал применяется после завершения текущего показа.

Юнит-тесты движка обязаны использовать поддельные часы и не зависеть от реального времени.

### 9.4. Фокусная буква

Считать графемы основного слова без ведущих и замыкающих кавычек, скобок и знаков препинания. Буквы, цифры и combining marks внутри слова сохраняются. Для определения основного диапазона использовать Unicode-свойства, а не проверку «буква ASCII».

Индексы:

- 1 графема — 0;
- 2–5 — 1;
- 6–9 — 2;
- 10–13 — 3;
- 14 и больше — 4;
- индекс ограничивать последней графемой.

Если в токене нет букв или цифр, фокусировать первую графему. Если основной диапазон после удаления пунктуации пуст, вернуться к первой графеме всего токена.

Отображение:

- центр фокусной графемы ставится на 40% ширины колонки чтения;
- ширина колонки не более 640 dp;
- базовая линия строки неподвижна;
- нельзя центрировать всё слово;
- нельзя центрировать bounding box каждого слова по вертикали;
- вертикальный центр области слова примерно 42% высоты безопасной области;
- для однострочного слова измерять фактический glyph-бокс после применения стиля;
- фокусная буква выделяется акцентным цветом и жирным начертанием;
- нельзя полагаться только на цвет.

Длинные слова:

- начинать с выбранного пользователем размера (по умолчанию 52 sp);
- уменьшать размер до минимальных 28 sp, если обычное слово не помещается в одну строку;
- не обрезать многоточием и не терять символы;
- если даже 28 sp не помещается в одну строку, разрешить до шести строк; для сегментов длиннее 40 графем допускается перенос по графемным границам;
- при многострочном исключении сохранять неизменный верхний левый угол области и не центрировать каждую строку отдельно;
- если после этих мер текст всё равно не помещается из-за системного масштаба, уменьшать размер до фактически необходимого, но не обрезать и не заменять символы;
- такое слово не должно выводиться быстрее, чем 600 мс;
- фокусная буква должна оставаться видимой и не попадать под системные панели или вырезы.

### 9.5. Границы предложений

Разбиение строить детерминированно по каноническому тексту и индексу. Граница предложения вычисляется один раз при импорте и не зависит от текущей темы, скорости или размера шрифта.

Конец предложения:

- `.`, `!`, `?`, `…` в конце токена;
- серия `?!`, `!!`, `...`;
- закрывающие кавычки и скобки после конечной пунктуации;
- конец абзаца, даже если знака нет.

Не считать концом:

- десятичную точку внутри числа;
- инициалы;
- распространённые сокращения `г.`, `т.`, `д.`, `др.`, `стр.`, `рис.`, `им.`, `ул.`, `т. д.`, `т. п.`;
- точку внутри URL.

Перед проверкой конца предложения отбросить завершающие парные кавычки и скобки, но не удалять их из отображаемого токена. Проверка сокращений и инициалов выполняется без учёта регистра и только для целого токена без завершающих смысловых знаков; например, `г.` не завершает предложение, а `г.!` завершает. Для неоднозначных случаев приоритет отдаётся сохранению предложения без разрыва: ложное объединение безопаснее ложного разделения.

Граница `CLAUSE` ставится после токена, который после отбрасывания завершающих кавычек и скобок заканчивается на `,`, `;`, `:` или тире. Точка, `!`, `?` и многоточие относятся к `SENTENCE`, а не к `CLAUSE`. Если токен одновременно заканчивает предложение и абзац, действует более сильная граница.

Точность сегментации не влияет на основной вывод слов. Ошибка может только немного изменить контекст и переходы по предложениям.

Для отображения текущего предложения на паузе нельзя загружать в Compose неограниченную строку. Если предложение длиннее 1000 графем, показать окно не более 1000 графем вокруг текущего слова с многоточием; навигация и `sentenceId` при этом продолжают работать по полному индексу.

### 9.6. Главы и завершение

Крупной считается верхнеуровневая глава, содержащая не менее 600 WORD-элементов. Порог задаётся константой `LARGE_CHAPTER_MIN_WORDS = 600` и не настраивается пользователем.

- После последнего слова последней верхнеуровневой главы книга завершается экраном `Completed`.
- Если автопауза глав включена, после крупной главы показывается `ChapterBreak` с названием следующей главы.
- После короткой главы при включённой автопаузе чтение продолжается автоматически; следующий заголовок, если он есть, отображается как визуальный элемент перед первым словом.
- Если автопауза глав выключена, `ChapterBreak` не наступает ни для какой главы; переходы между главами идут через обычные элементы и заголовки.
- Вложенные разделы не создают `ChapterBreak`.
- Пустой верхнеуровневый раздел остаётся в оглавлении как недоступный, не увеличивает видимый номер главы и не создаёт перерыв.
- При нажатии Play на `ChapterBreak` сразу показывается первый WORD-элемент следующей главы. Заголовок уже отображён на экране перерыва и повторно не показывается.
- На экране `ChapterBreak` сохранённой позицией остаётся последнее показанное слово предыдущей главы; Back сохраняет её и открывает библиотеку. При следующем Play сначала снова показывается перерыв, затем первое слово следующей главы.
- Заголовки и изображения не меняют счётчик прочитанных слов и не сдвигают процент назад.

Если в книге нет настоящих глав, используется одна синтетическая глава «Книга»; `ChapterBreak` для неё не создаётся.

### 9.7. Навигация

Левая кнопка:

- если текущее слово не первое в предложении — перейти к первому слову текущего предложения;
- если уже первое — перейти к началу предыдущего.
- если предыдущего предложения нет — кнопка неактивна.

Правая кнопка:

- перейти к первому слову следующего предложения;
- на последнем предложении быть неактивной.

Навигация по предложениям пересекает границы глав; переход не требует предварительного Play и не проходит через `ChapterBreak`. Если текущей позицией является заголовок или изображение, левая кнопка ведёт к началу текущего/предыдущего предложения по ближайшему слову, а правая — к следующему предложению. Переход к главе из `ContentSheet` начинается с первого элемента выбранного раздела.

Любая навигация:

- ставит/оставляет чтение на паузе;
- обновляет позицию;
- не запускает таймер.

## 10. Состояния и жизненный цикл

### 10.1. Состояния приложения

Навигационные маршруты:

- `Library`;
- `Reader(bookId)`;
- `Settings`.

Состояния читалки:

- `Loading`;
- `Paused`;
- `Playing`;
- `ChapterBreak`;
- `Completed`;
- `Error`.

Временные UI-состояния:

- `ContentsSheet`;
- `SpeedSheet`;
- `BookActionsSheet`;
- `NotesSheet`.

Временные панели не являются отдельными навигационными экранами и не восстанавливаются после смерти процесса.

### 10.2. Открытие

- Холодный запуск без сохранённого маршрута открывает библиотеку.
- Восстановление существующей задачи открывает последний маршрут, если он доступен и относится к существующей книге.
- Если это Reader, он всегда восстанавливается на паузе.
- Состояние `PLAYING` никогда не сохраняется.
- Книга всегда открывается на паузе.
- Прочитанная книга открывается экраном завершения.
- Если сохранённый маршрут содержит удалённую или `IMPORTING`-книгу, открывается библиотека с понятным уведомлением.
- Если книга существует, но не может быть восстановлена, открывается Reader в состоянии `Error`; кнопка «К библиотеке» завершает сценарий. Библиотека с уведомлением используется только для отсутствующей/недоступной записи маршрута.

В состоянии `Loading` показывается индикатор после 300 мс, если открытие ещё продолжается. Back отменяет загрузку и возвращает в Library; таймер не создаётся. Из-за необходимости пересобрать повреждённый производный индекс разрешено показать «Подготовка книги» с ручной отменой, но нельзя блокировать главный поток.

### 10.3. Фон и прерывания

При переходе Activity в `ON_PAUSE` или потерю активного окна, включая открытие системного диалога, вызов, переключение приложений, поворот экрана, блокировку устройства и сворачивание:

1. остановить таймер;
2. сохранить текущую позицию;
3. перевести чтение в `Paused`.

Если пользователь открыл системный диалог из Reader, после его закрытия Reader остаётся на паузе; повторный Play нужен явно. В `ON_STOP` повторно подтвердить `Paused` и выполнить идемпотентную запись, не воскрешая таймер.

При возвращении:

- показать ту же книгу;
- показать текущий элемент (WORD, заголовок или заглушку изображения);
- показать панель паузы;
- не запускать чтение автоматически.

Не нужен foreground service, медиауведомление или фоновая работа таймера.
Экран нельзя удерживать включённым вне `Playing`.

### 10.4. Back

- Из открытой панели: закрыть панель.
- Из Reader: сохранить позицию и открыть Library.
- Из Settings, открытых из Reader: вернуться в Reader на паузе.
- Из Settings, открытых из Library: вернуться в Library.
- Из Library: стандартный выход из приложения.

Перед любым уходом с Reader, включая Settings, чтение останавливается и позиция сохраняется по правилам раздела 7.4. Возврат из Settings никогда не возобновляет таймер автоматически.

### 10.5. Гонки

- Все команды проходят через один контроллер.
- У каждой сессии есть generation/session id.
- Результат загрузки устаревшей книги игнорируется.
- При смене книги сначала отменить старый таймер.
- Пауза от lifecycle имеет приоритет над отложенным Play.
- Старый `delay` не должен менять текущий элемент новой книги.
- Навигация, пауза, lifecycle-событие и завершение используют один последовательный dispatcher команд; запись позиции не может опередить более новую команду с тем же session id.
- Если после `ON_PAUSE` приходит отложенный `play` из нажатия, он игнорируется, пока Reader снова не окажется активен и пользователь не нажмёт Play.

## 11. Экраны и интерфейс

### 11.1. Общая навигация

Основные экраны:

```text
Library ↔ Reader
Library → Settings
Reader → Settings
```

Нет бокового меню и нижних вкладок. Временные диалоги выбора ZIP, подтверждения дубликата и системный файловый picker не являются маршрутами навигации. Открытие `Settings` из Reader не меняет сохранённую книгу.

### 11.2. Library

Заполненная библиотека:

```text
┌─────────────────────────────┐
│  Мои книги                ⚙ │
│                             │
│  ПРОДОЛЖИТЬ                 │
│ ┌─────┐ Мастер и Маргарита  │
│ │обл. │ Булгаков            │
│ └─────┘ Глава 7 · 43%       │
│                             │
│  Все книги                  │
│ ┌─────┐ Пикник на обочине ⋮ │
│ │обл. │ Стругацкие          │
│ └─────┘ 12% · Читается      │
│                             │
│ ┌─────┐ Дюна              ⋮ │
│ │обл. │ Герберт             │
│ └─────┘ 100% · Прочитано    │
│                        (+)  │
└─────────────────────────────┘
```

Поведение:

- карточка «Продолжить» показывается только при наличии `READY`-книги в `READING` и выбирает самую свежую по `lastOpenedAt`;
- прочитанные и непрочитанные книги находятся в общем списке;
- сортировка по `lastOpenedAt` по убыванию, при `null` — после открытых; затем по `importedAt` по убыванию;
- нажатие на карточку открывает книгу на паузе;
- `BROKEN`-книга остаётся в общем списке с заметным предупреждением; нажатие открывает ErrorScreen и не запускает чтение;
- `IMPORTING` и `DELETING` не видны пользователю;
- процент в карточке вычисляется по последнему показанному WORD, а не по индексу заголовка;
- «Продолжить» не появляется для `COMPLETED` и `UNREAD`;
- у каждой книги есть видимая кнопка `⋮`;
- `⋮`: «Открыть», «Начать сначала», «Информация», «Удалить»;
- долгое нажатие может дублировать меню, но не является единственным способом;
- свайп-удаление запрещено;
- `+` открывает импорт;
- `⚙` открывает настройки;
- позиция прокрутки списка сохраняется при возвращении из Reader;
- отсутствие обложки заменяется типографической заглушкой.

Для `BROKEN`-книги меню содержит «Подробности» и «Удалить»; «Начать сначала» и «Открыть» недоступны. «Подробности» не показывают стек и внутренние пути.

Пустая библиотека:

- книжная иллюстрация/иконка;
- заголовок «Здесь появятся ваши книги»;
- текст «Добавьте FB2 или FB2.ZIP»;
- основная кнопка «Добавить книгу»;
- краткая пометка «Книги хранятся на телефоне».

Удаление:

- требует подтверждения с точным названием;
- предупреждает, что файл и прогресс будут удалены;
- кнопка удаления визуально отличается от обычной.

Сброс:

- требует подтверждения при наличии прогресса;
- не удаляет книгу и не требует повторного импорта;
- сохраняет выбранную скорость книги;
- позиция становится на первое слово;
- `readingState=UNREAD`.

Выбор в ZIP:

- показывается снизу после успешной проверки архива;
- содержит относительный путь и размер;
- кнопки «Отмена» и выбор одного кандидата;
- после выбора применяется обычная проверка дубликатов;
- Back закрывает выбор и удаляет временный архив.

Диалог дубликата:

- содержит название найденной книги и вариант источника;
- действия «Открыть существующую», «Импортировать копию», «Отмена»;
- Back или отмена освобождают временную папку;
- повторное нажатие действия не создаёт параллельный импорт.

### 11.3. Reader: воспроизведение

Пока `Playing`:

- никаких кнопок, кроме слова;
- системные панели скрыты;
- внизу только тонкий индикатор прогресса;
- скорость и проценты не показываются;
- переходов и анимаций между словами нет;
- одно касание рабочей области ставит на паузу;
- Back возвращает в библиотеку;
- экран удерживается включённым.

Слово должно иметь семантическую подпись, но TalkBack-чтение всего потока не гарантируется. При наличии сноски маркер не активируется во время `Playing`: первое касание всегда ставит на паузу, чтобы чтение не проваливалось в сноску случайно.

### 11.4. Reader: пауза

```text
┌─────────────────────────────┐
│ ← Библиотека    Название ☰ ⋮│
│                             │
│    …и тогда он подумал,     │
│    что уже слишком поздно…  │
│                             │
│          слОВО              │
│                             │
│        ‹   ( ▶ )   ›         │
│                             │
│    −     300 слов/мин    +  │
│                             │
│ ▬▬▬▬▬▬▬▬▬▬▬▱▱▱▱▱▱▱▱▱▱▱▱▱▱▱ │
│ Глава 7 из 16 · 43%         │
└─────────────────────────────┘
```

Обязательное поведение:

- если текущий элемент — слово, оно остаётся на той же позиции, что во время чтения;
- фокусная буква не двигается;
- появляется лёгкое затемнение;
- системные панели возвращаются;
- управление не скрывается автоматически;
- пустое касание фона не продолжает чтение;
- продолжить можно только кнопкой Play;
- текущее предложение показывается максимум в трёх строках с многоточием, если соответствующая настройка включена; выключение настройки не сдвигает слово и фокусную букву;
- кнопки предыдущего и следующего предложения соответствуют разделу 9.7;
- `−` и `+` меняют скорость на 25;
- если текущий WORD имеет сноску, рядом с ним показывается компактный маркер без сдвига основного слова; нажатие на маркер открывает NotesSheet;
- нажатие на значение скорости открывает SpeedSheet;
- для книги с настоящими верхнеуровневыми главами отображается номер текущей главы и общее число глав; вложенный раздел не увеличивает этот счётчик;
- для синтетической книги без глав отображается только процент и общее название «Книга»;
- полоса прогресса в MVP неинтерактивна;
- `☰` открывает ContentSheet, если главы есть;
- `⋮` открывает BookActionsSheet;
- `← Библиотека` сохраняет позицию и выходит.

### 11.5. ContentSheet

- Занимает большую часть экрана снизу.
- Заголовок «Содержание».
- Иерархический список всех разделов с исходным или сгенерированным названием; отступ задаётся уровнем.
- Текущая глава выделена акцентной полосой и фоном.
- При открытии автоматически прокручивается к текущей главе.
- Нажатие закрывает панель и ставит выбранный раздел на первое доступное визуальное содержимое, но не запускает таймер.
- Если выбранный раздел содержит текст, первым текущим элементом становится первый WORD, а заголовок отображается в шапке Reader.
- Если раздел не содержит читаемых слов, выбор раздела недоступен и помечен как пустой.
- Для начала чтения из главы нужна кнопка Play.
- Back закрывает только панель.
- Если есть только синтетическая глава «Книга», кнопка не показывается.

### 11.6. NotesSheet

- Открывается только из маркера сноски на паузе.
- Заголовок «Сноска».
- Показывает текст всех сносок, прикреплённых к текущему слову, в порядке следования.
- Простые абзацы разделяются визуально; таблицы и стихи линеаризуются теми же правилами, что основной текст.
- Ссылки внутри сноски не открывают сеть; их видимый текст сохраняется, переходы не выполняются.
- Закрытие панели и Back возвращают к тому же слову в состоянии `Paused`.
- Если целью ссылки была отсутствующая сноска, маркер не показывается, а предупреждение доступно в информации о книге.

### 11.7. SpeedSheet

- Заголовок «Скорость».
- Текущее значение.
- Ползунок 100–800.
- Пресеты: 200, 300, 400, 500, 750.
- Пояснение: «Выше 500 — режим просмотра».
- Значение нормализуется к шагу 25; изменение сохраняется для книги сразу.
- Закрытие панели не запускает чтение.

### 11.8. BookActionsSheet

- «Начать сначала» с подтверждением.
- «Настройки чтения».
- «Информация о книге».
- Удаление здесь отсутствует.

Информация о книге:

- название и автор;
- язык;
- количество слов и глав;
- формат;
- дата добавления;
- размер на устройстве;
- предупреждения о пропущенных/упрощённых элементах.

### 11.9. ChapterBreak

- Наступает после последнего слова крупной верхнеуровневой главы, если автопауза включена.
- Показывает номер и название следующей главы.
- Не запускает следующую главу автоматически.
- Play начинает первое слово следующей главы.
- Back возвращает в библиотеку.
- Вложенные разделы не вызывают ChapterBreak.
- Порог крупной главы и поведение при выключенной автопаузе определены в разделе 9.6.

### 11.10. Completed

- Показывает «Книга прочитана», название книги.
- Кнопки «Читать заново» и «К библиотеке».
- «Читать заново» сбрасывает позицию после подтверждения.
- Книга получает `readingState=COMPLETED` и 100%.
- Завершённая книга не выбирается в карточку «Продолжить».
- Нажатие Back или «К библиотеке» сохраняет состояние и возвращает в Library.

### 11.11. Error

Экран ошибки книги:

- заголовок «Не удалось открыть книгу»;
- понятное объяснение;
- «К библиотеке»;
- опционально «Подробности» без стека и внутренних путей.

### 11.12. Первая подсказка

При первом открытии Reader показать один раз:

> Во время чтения коснитесь экрана, чтобы остановиться.

Подсказка не закрывает слово, не блокирует управление и не показывается повторно после первого Play или явного закрытия. Факт показа хранится в DataStore и не сбрасывается при повороте, перезапуске или открытии другой книги.

## 12. Настройки

Экран настроек содержит только:

- тему: системная, светлая, тёмная, сепия;
- размер слова 36–72 sp, по умолчанию 52;
- скорость по умолчанию 100–800, по умолчанию 300;

Автопауза глав влияет на будущие переходы и не переводит уже открытую книгу в другой экран задним числом. Порог «крупной главы» не показывается как отдельная настройка.

Не добавлять:

- пользовательские шрифты;
- настройку каждого типа паузы;
- выбор произвольного цвета;
- сложные схемы тем;
- статистику;
- аккаунт.

## 13. Визуальные правила

### 13.1. Темы

Светлая:

- фон `#F6F1E7`;
- основной текст `#211D18`;
- вторичный текст `#706960`;
- акцент `#9F3B34`.

Тёмная:

- фон `#171512`;
- основной текст `#F2EBDD`;
- вторичный текст `#A9A195`;
- акцент `#E07167`.

Сепия:

- фон `#E9DCC1`;
- основной текст `#2B2419`;
- вторичный текст `#6C5E49`;
- акцент `#9B4A37`.

Точные цвета могут быть слегка скорректированы для контраста, но визуальный характер и различие тем должны сохраниться.

Динамические цвета Material You в MVP отключены, чтобы темы оставались предсказуемыми. Для обычного текста контраст к фону должен быть не ниже 4.5:1, для крупного текста и графических элементов управления — не ниже 3:1. Фокусная буква должна оставаться различимой без одного только цвета. Контраст проверяется расчётом для всех трёх тем и подтверждается визуальной проверкой.

Акцентные цвета в базовой теме используются прежде всего для текста, иконок и индикаторов. Если элемент рисуется заливкой акцентным цветом, для текста/иконки на нём обязателен отдельный `onAccent` с контрастом не ниже 4.5:1. Ошибки и опасные действия используют отдельные Material-роли ошибки, также проверяемые на контраст.

### 13.2. Типографика

- UI: Material 3, одна системная sans-serif гарнитура.
- Слово чтения: хорошо читаемая serif-гарнитура.
- Допускается системный `FontFamily.Serif`; не добавлять сетевую загрузку шрифтов.
- Все строки интерфейса — в `strings.xml`, без жёсткого русского текста в коде.
- Высота строки и базовая линия основного слова не меняются от наличия предложения, маркера сноски или изменения скорости.
- Для слова применять системный масштаб шрифта вместе с пользовательским размером; итоговый размер ограничивать только защитой от выхода за экран по правилам раздела 9.4.

### 13.3. Анимации

- Появление/исчезновение панелей: 150–200 мс.
- Само слово не анимируется.
- Если в системе отключены анимации или включено уменьшение движения, переходы должны быть мгновенными; таймер не должен зависеть от анимаций.

### 13.4. Доступность

- минимальная область нажатия 48 dp;
- contentDescription у всех иконок;
- кнопки скорости, навигации, Play/Pause и закрытия панелей имеют явные текстовые или accessibility-метки;
- фокусная буква выделяется цветом и толщиной;
- контраст проверить в каждой теме;
- поддерживать системный масштаб шрифта минимум до 200%;
- интерфейс не должен клипаться или перекрывать элементы при масштабе 200%; длинные панели прокручиваются;
- маркер сноски имеет отдельную доступную цель и не перекрывает основное слово;
- полноценный TalkBack-режим чтения не входит в MVP, но ограничение должно быть описано в README.

### 13.5. Адаптивность

- Поддерживать портрет и ландшафт.
- При повороте ставить чтение на паузу и сохранять позицию.
- На планшете ограничивать колонку чтения 640 dp и центрировать её.
- Управление не растягивать от края до края на широких экранах.
- Слово не должно уходить под системные панели или вырезы.
- Использовать safe drawing insets и edge-to-edge без перекрытия интерактивных элементов.
- Цвет системных панелей и контраст их значков должны соответствовать выбранной теме; при скрытии панелей в `Playing` они восстанавливаются в `Paused` без скачка фокуса.
- В ландшафте при недостатке высоты панель паузы и листы должны прокручиваться, а не уменьшаться до недоступного размера.

## 14. Ошибки и сообщения

Минимальные случаи:

| Ситуация | Поведение |
|---|---|
| Файл недоступен | «Не удалось открыть файл. Возможно, он перемещён или недоступен.» |
| Файл слишком большой | Понятное сообщение о лимите |
| Нет места | «Недостаточно свободного места.» |
| Это не FB2 | «Файл не похож на книгу FB2.» |
| Повреждённый XML | «Не удалось прочитать книгу. Возможно, файл повреждён.» |
| Зашифрованный ZIP | «Архив защищён паролем.» |
| Несколько FB2 в ZIP | Показать выбор |
| Нет читаемого текста | «В файле не найден читаемый текст.» |
| Книга повреждена после импорта | `BROKEN`, предложить удалить/импортировать заново |
| Позиция не восстановлена | Ближайшее слово или начало главы с уведомлением |
| Ошибка сохранения | Не выбрасывать из книги, показать предупреждение |

Ошибки классифицируются внутренними стабильными кодами, например `IMPORT_SOURCE_UNAVAILABLE`, `IMPORT_LIMIT_EXCEEDED`, `IMPORT_UNSUPPORTED_ENCODING`, `IMPORT_BAD_XML`, `IMPORT_BAD_ZIP`, `BOOK_INTEGRITY`, `BOOK_REBUILD_FAILED`, `STORAGE_WRITE_FAILED`, `POSITION_SAVE_FAILED`. Код не является пользовательским текстом; UI сопоставляет его с локализованным сообщением и безопасным следующим действием.

При ошибке импорта должно быть указано, можно ли повторить выбор, выбрать другой файл или удалить уже добавленную книгу. Отсутствующая сноска или неподдерживаемый декоративный элемент не считаются фатальной ошибкой, если основной текст читается: они попадают в предупреждения книги.

Нельзя:

- показывать стек исключения;
- показывать абсолютные внутренние пути;
- логировать фрагменты книги;
- запускать книгу с начала без уведомления при потере позиции;
- оставлять пользователя на белом экране.
- бесконечно повторять неудачную запись или восстановление без сообщения пользователю.

## 15. Автотесты и приёмочные проверки

### 15.1. Unit-тесты токенизации

Обязательно покрыть:

- обычное слово;
- слово с запятой;
- слово с кавычками;
- длинное тире в начале реплики;
- `кто-то`;
- десятичное число;
- инициалы;
- сокращение;
- многоточие;
- URL;
- очень длинное слово;
- токен длиннее 96 графем делится без потери символов и не разрывает grapheme cluster;
- сноска у разделённого токена прикрепляется к последнему сегменту;
- пунктуация после inline-тега;
- слово, разрезанное inline-тегами без пробела;
- сохранение авторского пробела между inline-фрагментами;
- неразрывный пробел;
- одиночная пунктуация между пробелами;
- пустой блок;
- заголовок не увеличивает `wordCount`;
- позиции смещений в UTF-16;
- emoji и surrogate pair в окружении слова;
- базовые grapheme clusters с combining marks;
- текст CJK без пробелов отображается как один токен в пределах лимита;
- слова из стихов;
- сноски не увеличивают количество слов.

### 15.2. Unit-тесты движка

- базовый интервал для каждого значения 100–800 с шагом 25;
- округление длительности до целого;
- приоритет границ;
- отсутствие суммирования пауз;
- задержка старта/возобновления;
- возобновление после паузы с новой полной задержкой;
- переход по предложениям;
- завершение последнего слова;
- `Completed` наступает после финальной задержки, а не вместе с показом последнего слова;
- single active timer;
- повторный Play;
- пауза отменяет таймер;
- задержка на один интервал не пропускает слова;
- длинная задержка не перескакивает через несколько слов;
- смена скорости применяется при следующем запуске или со следующего элемента, если она произошла программно;
- глобальная скорость используется для книги без `lastSpeedWpm`, а после первого Play или ручной смены сохраняется независимо от глобальной;
- визуальные HEADING/IMAGE имеют собственный dwell и не увеличивают прогресс;
- переход `ChapterBreak` при главе в 599, 600 и более слов;
- выключенная автопауза не создаёт `ChapterBreak`;
- последнее слово единственной главы ведёт в `Completed`, а не в `ChapterBreak`;
- lifecycle Pause побеждает конкурирующий отложенный Play;
- результат старой session id не меняет новую книгу.

### 15.3. Unit-тесты фокуса

- длина 1;
- 2–5;
- 6–9;
- 10–13;
- 14+;
- кириллица с `ё` и `й`;
- ведущие и замыкающие кавычки;
- только пунктуация;
- emoji ZWJ-последовательности;
- буква с combining mark;
- дефис;
- число;
- неразрывный пробел;
- отсутствие порчи grapheme clusters.

### 15.4. Тесты импорта

Фикстуры:

- простой UTF-8 FB2;
- UTF-8 с BOM и без BOM;
- Windows-1251;
- UTF-16 LE и BE с BOM;
- конфликт BOM и XML declaration;
- недействительная последовательность выбранной кодировки;
- необъявленная неизвестная кодировка;
- FB2 без глав;
- несколько основных body;
- текст до первого section;
- сверхдлинные метаданные и сноска усекаются по графемной границе с предупреждением;
- вложенные разделы;
- пустой/безымянный раздел;
- стихи;
- эпиграф;
- сноски;
- несколько сносок у одного слова;
- отсутствующая цель сноски;
- таблица;
- неизвестный тег;
- обложка;
- повреждённая обложка;
- изображение в body;
- `.fb2.zip` с одной книгой;
- ZIP с несколькими книгами;
- ZIP без FB2;
- ZIP с регистром расширения `.FB2`;
- ZIP с ошибочным расширением, но корректными magic bytes;
- сырой XML с расширением `.zip`, который определяется как FB2 по содержимому;
- ZIP с неверным CRC;
- ZIP с несколькими одноимёнными отображаемыми путями;
- ZIP-запись с `../` в имени не создаёт файл вне папки импорта;
- повреждённый XML;
- не-FB2;
- слишком большой файл;
- попытка XXE;
- `DOCTYPE` и внутренние сущности;
- глубина XML выше лимита;
- слишком длинное значение атрибута;
- ZIP bomb в пределах тестового лимита и за его границей.

Фикстуры должны быть синтетическими или public domain, не включать чужие защищённые книги.

Для каждой поддерживаемой кодировки проверить одинаковый канонический результат. Для ZIP проверить, что выбранный внутренний путь сохраняется в манифесте и используется при пересборке индекса.

- идемпотентное завершение удаления после падения;
- остатки временных файлов;
- удаление книги;
- сброс прогресса;
- миграция позиции при смене индекса;
- падение в любой точке пересборки не оставляет смешанный набор файлов и сохраняет читаемую книгу;

- удаление старой книги не затрагивает другие;

### 15.7. Производительность и устойчивость

На эмуляторе или устройстве, указанном в отчёте, проверить:

- импорт синтетической книги с близким к допустимому размером текста не приводит к OOM и не выполняет парсинг в UI-потоке;
- открытие книги с 1 миллионом слов не блокирует главный поток на время загрузки и показывает индикатор;
- таймер не создаёт заметного роста памяти на протяжении 10 минут ускоренного теста;
- при 750 WPM на 60 Hz за 2 минуты реального воспроизведения не пропускается ни один WORD;
- UI остаётся отзывчивым на паузу и кнопку Back во время чтения;
- запись позиции не вызывает заметных пауз между словами;
- отмена импорта реагирует не дольше чем через 1 секунду после безопасной точки.

Если требуемое оборудование отсутствует, это фиксируется в README и итоговом отчёте как непройденная проверка, а не как автоматический успех.

Если доступен эмулятор или устройство:

```text
.\gradlew.bat connectedDebugAndroidTest
```

Дополнительно вручную проверить на эмуляторе/устройстве:

- 60 Hz и, если доступно, 120 Hz;
- 750 WPM;
- сворачивание и возврат;
- открытие системного диалога и звонок/имитация `ON_PAUSE`;
- блокировку экрана;
- поворот;
- смерть процесса;
- установку и открытие на минимальной поддерживаемой API и целевой API;
- Android Backup и device-to-device transfer отсутствуют;
- merged manifest не содержит `INTERNET` и широких storage permissions;
- APK не содержит тестовых фикстур и чужих книг.

Все три обязательные Gradle-команды должны завершиться успешно. `lintDebug` не должен содержать ошибок уровня error; предупреждения зависимостей фиксируются в отчёте, предупреждения кода проекта исправляются или обосновываются.

## 18. Критерии готовности

Работа считается завершённой только если:

- приложение собирается обязательными Gradle-командами из раздела 15.8;
- запускается на чистом устройстве;
- импортирует синтетические представительные FB2, FB2.ZIP и FBZ во всех обязательных кодировках;
- при наличии нескольких FB2 в ZIP пользователь выбирает одну книгу, а выбранный путь сохраняется для восстановления;
- импорт атомарен: после прерывания на любом этапе библиотека не показывает частичную книгу, временные файлы очищаются или восстановление безопасно завершается;
- книга читается после удаления внешнего источника;
- при удалении внешнего файла повторный импорт того же URI не требуется;
- открытие книги не запускает чтение;
- касание ставит на паузу;
- продолжение возможно только через Play;
- пауза на lifecycle, Back и смена книги не могут «воскресить» старый таймер;
- фокусная точка стабильна визуально;
- 750 WPM не пропускает слова в автоматическом визуальном тесте и в двухминутной ручной проверке;
- скорость сохраняется для книги;
- переходы по предложениям работают;
- оглавление и переходы по вложенным разделам работают;
- сноски открываются из паузы и не попадают в основной поток;
- заголовки и изображения не увеличивают `wordCount`;
- крупная глава останавливает чтение, короткая продолжается автоматически; выключенная автопауза не создаёт остановок;
- позиция сохраняется при выходе, фоне и смерти процесса; при активном чтении допустимое расхождение не более одной секунды, при ручной паузе и уходе в фон текущий элемент восстанавливается точно;
- пересборка индекса из сохранённого источника и восстановление после незавершённого импорта проверены тестами;
- прочитанная книга получает корректный статус;
- удаление и сброс работают;
- повреждённые, чрезмерно глубокие и небезопасные файлы не вызывают аварийного завершения или OOM;
- XXE, внутренние сущности, ZIP bomb, неверный CRC и path traversal заблокированы;
- отсутствующие обложка и необязательные элементы не ломают импорт;
- приложение не требует интернета;
- в манифесте нет `INTERNET`;
- нет доступа ко всей внешней памяти;
- обязательные unit/storage-тесты и все выполненные Compose UI/instrumented-тесты проходят; недоступность эмулятора/устройства не позволяет называть эти проверки пройденными и должна быть явно указана в отчёте;
- lintDebug завершается без ошибок;
- портрет, ландшафт, системный масштаб до 200% и длинные слова не обрезают элементы управления или основное слово;
- сформирован debug APK;
- README содержит точные версии окружения, ограничения и результаты непроведённых проверок;
- в репозитории и APK нет защищённых чужих книг и тестовых навигационных обходов.

## 19. Что делать при неопределённости

1. Искать ответ в этом документе версии 2.0; исходную версию 1.0 не использовать как дополнение.
2. Если ответа нет, выбрать минимальное решение, не добавляющее новых экранов, серверов, аккаунтов или внешних сервисов.
3. Записать решение в описании Issue или Pull Request с указанием причины и
   влияния на тесты.
4. Продолжить реализацию.

Останавливаться и запрашивать пользователя только если:

- отсутствует Android SDK или среда не позволяет собрать проект;
- требуются учётные данные или подпись для внешнего сервиса;
- для продолжения нужно выйти за пределы явно разрешённых файлов/систем;
- обнаружено противоречие, которое нельзя решить без изменения пользовательского поведения.

Нельзя останавливаться только потому, что интерфейс выглядит субъективно спорным. Визуальные решения зафиксированы выше.
Нельзя менять пользовательское поведение, границы MVP или требования безопасности только потому, что их проще реализовать иначе. Такое изменение требует отдельного решения пользователя.

## 20. Вне MVP

Следующие функции не реализовывать в MVP:

- EPUB, PDF, MOBI;
- поиск;
- множественные закладки;
- заметки, выделения и цитаты;
- показ фраз из двух-трёх слов;
- обычный текстовый режим;
- полноценный TalkBack-режим;
- TTS;
- словарь и перевод;
- ИИ;
- статистика и достижения;
- аккаунт и синхронизация;
- облачный бэкап;
- магазин и скачивание книг;
- полный просмотр иллюстраций;
- настройка каждого параметра паузы;
- пользовательские шрифты;
- виджеты и Wear OS;
- кроссплатформенность.

Эти функции можно добавить только после отдельного решения пользователя. Наличие архитектурной точки расширения не является разрешением реализовывать функцию сейчас.

## 21. Итоговая формула продукта

«кАдр» — это спокойная, локальная и предсказуемая Android-читалка, которая хорошо открывает обычные FB2, показывает их по одному слову с неподвижной фокусной точкой, позволяет регулировать темп и надёжно возвращает читателя к последнему подтверждённому месту после паузы, сворачивания или восстановления книги.

| Слабое место версии 1.0 | Решение версии 2.0 |
|---|---|
| Неясно, какая версия ТЗ действует рядом с сохранённым исходником | Явно разделены области применения 1.0 и 2.0; исходный файл не изменяется |

| Для `ACTION_SEND`/`ACTION_VIEW` не были определены количество файлов, разрешения и фильтры | Принимается ровно один поток; временное чтение без persistable-доступа; MIME проверяется содержимым |
| ZIP-выбор не сохранял выбранную внутреннюю книгу | Путь выбранной записи хранится в манифесте и БД |
| Ограничения не покрывали длинные XML-события, сноски, число слов и разумное декодирование обложки | Добавлены явные лимиты и требования к потоковой проверке |
| Атомарность файловой системы и Room была описана недостаточно строго | Введена commit-точка через manifest и восстановление после падения между переносом и обновлением Room |
| Заголовки/изображения не имели однозначной модели позиции | Введена последовательность `ReadingItem` с отдельным `itemOrdinal`; прогресс считается только по WORD |
| «Крупная глава» не имела определения, а `ChapterBreak` и настройка противоречили друг другу | Зафиксирован порог 600 слов и поведение для коротких глав/выключенной автопаузы |
| Сноски были объявлены, но пользовательский сценарий отсутствовал | Добавлен NotesSheet и правило активации маркера на паузе |
| Сохранение «точно» при фоне зависело от успешной асинхронной записи Room | Введён синхронный `SavedStateHandle` checkpoint и идемпотентная запись Room |
| Планировщик допускал неоднозначную компенсацию опозданий | Запрещён переход через несколько элементов; заданы правило сброса интервала и тесты |
| Очень длинные слова могли обрезаться при масштабе шрифта | Добавлены многострочный fallback, защита от потери символов и минимальный dwell |
| Патологический токен без пробелов мог перегрузить Compose | Логические токены длиннее 96 графем безопасно делятся на сегменты без потери текста |
| Ошибочное состояние книги и восстановление индекса не были разделены | `BROKEN` ставится только после неудачи восстановления; отсутствующий производный файл сначала пересобирается |
| Проверки были перечислены, но не образовывали полную матрицу безопасности и приёмки | Добавлены кодировки, XML/ZIP-атаки, recovery-состояния, notes/UI, производительность и точные Gradle-проверки |
| Итоговая формула обещала больше, чем гарантировала спецификация | Формулировка приведена к реальной гарантии по последней подтверждённой позиции |
